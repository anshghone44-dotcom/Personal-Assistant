PHASE 1 — FOUNDATION, AUTHENTICATION & DATABASE

Build Phase 1 of my premium multilingual conversational AI calendar and reminder assistant.

IMPORTANT:
Only build Phase 1.
Do NOT build voice, AI conversation, calendar UI, reminders UI, memory UI, or advanced animations yet.

The goal of Phase 1 is to create a clean, production-ready foundation that the later phases can build on.

==================================================
1. PRODUCT
==================================================

The application is a voice-first personal AI assistant.

Core future experience:

User:

5. DATABASE
==================================================

Create the following PostgreSQL tables.

------------------------------------------
TABLE: profiles
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
name TEXT
timezone TEXT
preferred_language TEXT
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

Each authenticated user should have one profile.

Default:

preferred_language = "en"

timezone should be detected where possible but allow the user to change it later.

------------------------------------------
TABLE: conversations
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
title TEXT
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

------------------------------------------
TABLE: messages
------------------------------------------

Fields:

id UUID PRIMARY KEY
conversation_id UUID REFERENCES conversations(id)
user_id UUID REFERENCES auth.users(id)
role TEXT
content TEXT
language TEXT
created_at TIMESTAMPTZ

role should eventually support:

user
assistant
system

Add appropriate constraints.

------------------------------------------
TABLE: people
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
name TEXT
relationship TEXT
notes TEXT
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

Examples:

Rahul
Investor

Mom
Family

John
Friend

------------------------------------------
TABLE: events
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
title TEXT
description TEXT
person_id UUID REFERENCES people(id)
start_time TIMESTAMPTZ
end_time TIMESTAMPTZ
timezone TEXT
location TEXT
status TEXT
source TEXT
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

status can eventually support:

scheduled
cancelled
completed

source can eventually support:

manual
ai
calendar_sync

------------------------------------------
TABLE: reminders
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
title TEXT
description TEXT
trigger_time TIMESTAMPTZ
timezone TEXT
related_event_id UUID REFERENCES events(id)
status TEXT
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

status:

pending
completed
cancelled

------------------------------------------
TABLE: memories
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
memory_type TEXT
content TEXT
importance INTEGER
confidence NUMERIC
source_message_id UUID REFERENCES messages(id)
created_at TIMESTAMPTZ
expires_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

IMPORTANT:

Do NOT automatically save every conversation as memory.

The future AI system will decide what information is important enough to store.

------------------------------------------
TABLE: preferences
------------------------------------------

Fields:

id UUID PRIMARY KEY
user_id UUID REFERENCES auth.users(id)
preference_key TEXT
preference_value JSONB
created_at TIMESTAMPTZ
updated_at TIMESTAMPTZ

Examples:

preferred_reminder_time
preferred_language
working_hours
notification_preferences

==================================================
7. ROW LEVEL SECURITY
==================================================

This is extremely important.

Enable Row Level Security on every user-owned table.

Users must only be able to:

SELECT their own data
INSERT their own data
UPDATE their own data
DELETE their own data

A user must NEVER be able to access another user's:

- conversations
- messages
- people
- events
- reminders
- memories
- preferences
- profile

Create proper Supabase RLS policies.

Do not use insecure "allow all" policies.
